# 淘金币助手 v1.2

一个基于 **Shizuku + OCR** 的淘金币自动任务小工具 APP。

> 本仓库 fork 自 [Doplars/TaobaoCoinAssistant](https://github.com/Doplars/TaobaoCoinAssistant) v1.1。
> v1.2 的改动集中在**输入层**：把原来的 `input tap / input swipe` 换成生理级轨迹仿真，
> 并新增运行时拟人度自检。v1.1 及更早的内容归原作者所有，文末更新日志中保留。
>
> 改造过程中的问题、诊断与处理方式记录在 **[DEVLOG.md](DEVLOG.md)**。

---

## 软件原理

1. 使用 **Shizuku** 执行 `screencap` 获取当前屏幕；
2. 使用 **ML Kit OCR** 识别页面文字与任务区域；
3. 根据识别结果判断当前页面状态；
4. 再通过 **Shizuku** 执行点击、滑动、输入、返回、启动淘宝等操作。

运行链路：

`Shizuku 截图 → OCR 识别 → 状态判断 → Shizuku 点击/滑动/输入`

## 软件功能

- 自动从淘宝首页进入 **淘金币** 页面；
- 自动识别并处理 **赚更多金币 / 展开 / 任务列表**；
- 支持 **新旧版淘金币界面**，会通过 OCR 自动识别任务面板特征，无需手动切换；
- 支持 **普通浏览 / 搜索任务 / 跨应用跳转任务**；
- 支持 **自定义黑名单、跳转任务名单、搜索任务名单、普通浏览名单**；
- 支持 **顶部悬浮状态条**（可选）与一键停止；
- 主界面支持 **自适应滚动**，兼容不同屏幕高度、分辨率与 DPI；
- 悬浮状态条会自动避开 **状态栏/刘海安全区域**；
- 遇到 **安全验证** 会自动停止，避免误操作；
- 纯截图 OCR 识别，尽量规避 UC WebView 旧节点问题；
- 收尾前会**强制滑回任务面板顶部复查未完成任务**，确认没有可执行任务后才领奖结束；
- 运行日志保留更多历史记录，并在每次开始执行时加入分隔线；
- **（v1.2）** 所有点击与滑动走生理级轨迹仿真，不再是匀速直线；
- **（v1.2）** 运行结束输出一份拟人度自检报告。

## v1.2：输入层做了什么

原来的 `input swipe x1 y1 x2 y2 duration` 是**线性插值**：完美直线、恒定速度、端点不减速。
`input tap` 则每次都点在**同一个像素**上。再加上固定的 `sleep()`，整条操作序列的机器特征很硬。

v1.2 在 Shizuku 的 shell 侧生成轨迹，然后**逐点注入**（`InputManager.injectInputEvent`）：

| 维度 | 做法 |
|---|---|
| 路径 | 三次贝塞尔，控制点按垂直方向随机偏移（`bow = 1.8%~6.8% × 距离`，符号随机）；第二个控制点略微越过终点，制造末段过冲回拉 |
| 速度剖面 | 最小 jerk 五阶多项式 `s = 10t³-15t⁴+6t⁵`（首尾速度与加速度均为 0，jerk 有界）；用 `s(t^γ)` 做时间重参数化：γ≈1.0 精确定向移动，γ≈0.88 甩动（加速快、减速长） |
| 时长 | Fitts 模型 `T = 0.10 + 0.18·log₂(D/W+1)` 秒，夹紧 320~900ms，甩动再乘 0.74~0.90 |
| 震颤 | 8~12Hz 主频 + 二次谐波，双轴独立相位，振幅 0.55~1.4px；采样间隔 8ms（12Hz 需要 ≤41ms，不会混叠） |
| 点击抖动 | 高斯 σ=2.2px，叠加每 4 秒随机游走、上限 ±1.8px 的慢漂移偏置；抖动被夹在按钮半宽半高内，不会点歪 |
| 按压过程 | 按下后停留 55~110ms，含 1~2 次亚像素游走，压力先升后降 |
| 等待间隔 | 对数正态（σ=0.30）+ 4% 概率重尾（走神），替换了全部固定 `sleep()` |
| 兜底 | 反射注入失败自动回退 `input` 命令，功能不中断，日志只提示一次 |

实测（500 次采样）：点击 σ=2.15px、最大 5px、0 次出按钮；定向滑动 338ms、速度峰值在 0.50；
甩动 278ms、峰值在 0.44；900px 行程偏离直线 22px；`sleep(1800)` 实际均值 1945ms、范围 990~4320ms。

代码：`HumanMotion.java`（采样，纯 Java）、`MotionInjector.java`（注入）、`CoinUserService.TRANSACTION_INJECT`。

## v1.2：运行时自检怎么用

`MotionAudit` 会记录**本 App 自己发出的每一个手势**的客观指标，跑完给一份报告，用来定位「哪一步还是机器特征」。

**开关**：主界面「拟人度自检（可选）」，**默认关闭**。关闭时完全不记录、零开销，也不会产生任何日志；打开后本次运行结束会在日志末尾输出报告，每 25 次动作出一份简报。

记录的指标：

| 指标 | 含义 | 扣分阈值 |
|---|---|---|
| 注入通道 | 是否回退到 `input` 命令 | 有降级就按占比重扣 |
| 间隔变异系数 CV | 相邻动作间隔的离散程度 | CV<0.12 重扣，<0.25 / <0.40 轻扣 |
| 点击抖动 | 落点相对按钮中心的偏移 | 均值 <1.2px 重扣，<2.0px 轻扣 |
| 落点重复率 | 连续点击落在同一像素的比例 | >30% 扣分 |
| 震颤强度 | 轨迹高频分量 RMS | <0.35px 占比 >30% 扣分 |
| 轨迹弧度 | 偏离弦长 / 弦长 | <0.4% 占比 >30% 扣分 |
| 速度峰值位置 | 应在行程中段 | 落在 <0.2 或 >0.8 占比 >30% 扣分 |
| 操作密度 | 间隔 <300ms 的占比 | >25% 扣分 |

评分 100 起扣，≥80 低 / 60~79 中 / <60 高。**每 25 次动作**在日志里打一份 `[自检 N]` 简报，
运行结束打完整报告，另外每次手势的抖动/震颤/弧度/峰值也会逐条进日志，方便定位到具体哪一步。

> 注意：这个分数衡量的是「动作形态像不像人手」，**不代表平台会不会判定**。
> 它只是自查工具，用来发现实现上的漏洞（比如某处忘记加抖动、某段间隔恒定）。

## 运行方法

### 1）Shizuku 权限

- 先安装并启动 **Shizuku**；
- 在本 App 中点击 **“授权 Shizuku”**；
- 确认淘宝已经安装并登录。

> 非 Root 场景下，手机重启后通常需要重新启动 Shizuku 服务，这是 Shizuku 的正常使用方式。

### 2）悬浮窗权限（可选）

开启“顶部悬浮状态条”才需要“显示在其他应用上层”权限；不开启则不需要。

### 3）确认轨迹仿真有没有生效

- 开发者选项打开 **「指针位置」**，跑一次任务：屏幕上画出的是**带弧线和毛刺的点列**就对了；
  如果是一条笔直的匀速线，说明还在走 `input` 命令降级。
- 日志里出现「逐点注入不可用，已回退 input 命令」同理，此时轨迹仿真没有生效（功能仍可用）。

## 构建

- **云构建**：push 到 `master` 会自动触发 `.github/workflows/build-apk.yml`，也可以在 Actions 页手动 `Run workflow`；产物只有一个，文件名带版本号，例如 `TaobaoCoinAssistant-v1.2.1-debug.apk`（arm64-v8a，现代安卓手机通用）。
  > fork 出来的仓库 GitHub Actions 默认关闭，需要先在 Actions 页点一次启用。
- **本地**：Android Studio 打开项目 → Sync → `Build > Build APK(s)`，或 `gradle :app:assembleDebug`（JDK 17 + Gradle 8.13 + Android SDK 36）。

## ⚠️ 风险说明（请读完再用）

1. **可能违反平台规则。** 用脚本代替人工完成淘金币任务，通常不符合淘宝等平台的用户协议。是否使用由你自己决定并承担后果。
2. **拟人化 ≠ 不会被检测到。** 上面的轨迹仿真只解决「触摸动作形态」这一个维度；平台侧还可以看账号行为、设备指纹、任务完成速度分布、服务端埋点、以及 OCR 无法感知的很多信号。**本项目没有任何能力、也不宣称能规避这些。** 自检分数高只说明动作像人，不代表账号安全。
3. **不要改造成绕过验证。** 代码中「遇到安全验证即停止」是刻意设计，请不要改成自动破解。
4. **仅限自用学习。** 不要做批量账号、不要商用、不要分发给他人批量运行。
5. **误点风险始终存在。** OCR 受机型、分辨率、页面活动样式影响，首次运行务必盯着手机。
6. **需要 Shizuku（Android 11+）**，手机重启后通常要重启一次 Shizuku。

本项目仅供学习与研究自动化流程，请自行评估使用风险。

## 更新日志

### v1.3.0（本 fork）

行为层拟人化——v1.2.2 跑通后，手势层已经没问题（自检 100 分），但日志里的行为特征更明显，这一版专门处理这些：

- **浏览时长随机化**：原来每个任务都恰好浏览 22 秒，现在 18~34 秒随机；
- **执行顺序不再固定**：改为「前 3 个候选里随机挑一个」，优先级仍参与排序，但不再永远执行列表第一个；
- **滑动方向随机**：70% 向上、30% 向下小幅回看（原来只有向上）；
- **列表滚动起止点整段随机**（原来固定在 x=0.278w、y=0.844h→0.281h）；
- **每完成 3 个任务随机停顿 3~12 秒**；
- **轨迹弧度放宽**到行程的 1%~12%，另有 10% 概率接近直线；
- **跨应用跳转确认自动处理**：跳到支付宝时弹出的「是否打开 / 允许」确认框会自动点掉，不再需要人工点；
- **修复跨应用任务误分类**：`external()` / `isSearch()` 改用模糊匹配。之前 OCR 把「金豆夺宝」认成「金豆寺宝」，导致本该跨应用的任务被当普通浏览执行。

> 版本号 1.3.0；`USER_SERVICE_VERSION` 升到 5（`HumanMotion` 也在 shell 侧运行，改了必须同步 +1，否则改动不生效）。

### v1.2.2（本 fork）

- **再次修复任务面板被误判成遮挡弹窗**（第一次修得不够）：根本原因是判据方向错了——把「能看到任务面板/可信任务列表」当成弹窗的**背景证据**，而能看清任务列表恰恰说明**没有被遮挡**。现在改为：`isTrustedTaskContext() && countActionRows() >= 2` 时直接跳过弹窗判定；冷却 2.5s → 6s；剔除 `金币额外抵扣` 这类淘金币页面常规文案；首页要求至少 2 个强文案；触发线 3 → 4。
- **修复 shell 侧代码更新不生效**：Shizuku 按 `version` 决定是否复用已启动的 UserService 进程，之前改了 `CoinUserService` 却没升版本，手机上跑的一直是旧代码（表现为自检抖动恒为 0.00px、落点重复率虚高 38%）。现在把版本号独立成 `USER_SERVICE_VERSION`，改动 shell 侧代码必须 +1。
- 版本号升到 1.2.2（`versionCode` 108）。

### v1.2.1（本 fork）

- **修复任务面板被误判成遮挡弹窗**：刚打开面板的 2.5 秒内不做弹窗判定；中部 CTA 宽度门槛 0.18 → 0.35 屏宽；新增必要条件——必须命中至少 1 个高特异弹窗文案或宽度 > 0.45 屏宽的大 CTA，否则视为任务面板本身，不执行 Back。（现象：面板一打开就被 Back 关掉，反复重进，最终退到桌面，一个任务都没跑。详见 DEVLOG。）
- **修复自检「累计动作 0 次」的显示错误**：样本不足的返回路径没填 `totalActions`，实际记录数是对的；提示改为显示具体次数。
- 新增 `DEVLOG.md`，记录改造过程中的问题与处理方式。

### v1.2（本 fork，基于上游 v1.1）

- **生理级轨迹仿真**：新增 `HumanMotion`（贝塞尔路径 + 最小 jerk 剖面 + 8~12Hz 双频震颤 + Fitts 时长 + 点击高斯抖动与慢漂移偏置 + 非均匀延迟）与 `MotionInjector`（shell 侧反射 `injectInputEvent` 逐点注入，异常路径补发 `ACTION_UP`）。
- **手势全面替换**：点击、列表滚动、回顶、浏览滑动改走 `humanTap` / `humanSwipe`；`sleep()` 内部改为非均匀采样，一处改动覆盖全部等待点。
- **新增运行时自检**：`MotionAudit` 记录每次手势的抖动/震颤/弧度/速度峰值/注入通道/间隔，每 25 次动作出简报，结束出完整报告，量化「还有多少机器特征」。
- **注入协议扩展**：`CoinUserService` 新增 `TRANSACTION_INJECT`，回复中回传手势统计；`ShizukuShell.injectGesture` 返回 `GestureResult`。
- **降级与兜底**：hidden API 被拦时回退 `input` 命令（日志只提示一次），并补 `org.lsposed.hiddenapibypass:6.1` 依赖提高注入成功率。
- **构建修复**：去掉在新版 runner 上会失败的 `android-actions/setup-android@v3`，改用 runner 自带的 `sdkmanager` 安装 SDK。
- README 重写：补充输入层原理、自检用法与风险说明。

### v1.1（原作者 Doplars）

- **全分辨率界面适配**：主界面改为整页可滚动布局，兼容不同屏幕高度、DPI 与分辨率；顶部悬浮状态条会自动避开状态栏和刘海安全区域。
- **淘金币入口识别增强**：扩大淘宝首页 OCR 导航范围，并优先使用 ML Kit Element 级文字边界；当“领淘金币”和相邻快捷入口被合并识别时，会按文字在合并区域中的相对位置计算点击点，降低误点“阿里拍卖”等相邻入口的概率。
- **通用遮挡弹窗自动恢复**：针对淘宝闪购、金币抵扣、加购抵金、桌面组件、出行优惠等多种覆盖式弹窗，不依赖固定 X 坐标或某一种广告文案；通过“预期页面上下文 + 弹窗特征/中部 CTA”综合判断后，优先执行一次系统 Back 关闭，再用下一帧 OCR 验证并继续原流程。
- 任务列表继续使用较高分辨率 OCR，黑名单支持保守模糊匹配，降低形近字误识别造成的误执行。
- 新旧版淘金币任务面板共用同一套状态机，无需手动选择版本。
- 收尾阶段始终先向上滑回顶部，并复查是否还有未完成且不在黑名单中的任务；有则继续执行，没有才领奖并结束。
- 经典版只有明确识别到“今日累计奖励”时才会点击累计奖励槽，不再使用固定坐标兜底，避免误点第一条任务。
